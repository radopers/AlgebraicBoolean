AlgebraicBoolean

From Boolean networks to polynomials and back

Translate logic gates into ordinary arithmetic, reduce repeated variables, and recover exactly the input rows that make the result true.

1. Where the method began

Rado’s 2013 notes grew out of a question about optimal Golomb rulers. Could a search for distances be expressed through constraints on binary digits, then worked through using ordinary arithmetic? AlgebraicBoolean represents each signal by a polynomial, carries out the logic in that form, and converts the result back into a Boolean expression.

The method describes the same finite Boolean functions as a truth table or a gate network. Its distinctive working form is an expanded polynomial with a simple rule for repeated variables. That gives us a way to calculate symbolically, recognize equivalent outputs, and recover the assignments that make an output true.

Boolean network→ Reduced polynomial→ Complete true rows

2. From Boolean gates to polynomials

The coefficients use ordinary arithmetic. The 2 in the XOR formula is essential. Start with a variable for each input and a constant for each fixed signal. Process the gates in an order in which each gate’s inputs are already available. If a network has several outputs, keep a polynomial for each one.

Reduce powers after multiplication

Expand the products, replace each positive power of an input variable by that variable, and collect terms with the same variables. The power rule preserves values at both Boolean inputs.

xik→xi,k≥1.

For example, the contradiction A AND NOT A reduces to zero.

a⁢(1−a)=a−a2→a−a=0.

The reduction rule expresses equality on Boolean inputs. Ordinary real inputs outside 0 and 1 may give different values before and after reduction.

Fix the complete input set N with n inputs. A subset S of N identifies the monomial xS, the product of the variables in S. The empty subset represents 1. Write x for the full input vector. Every reduced polynomial has the form

p⁡(x)=∑S⊆NcS⁢xS.

There are 2n possible monomials, including the constant. Multiplication combines their sets of variables by union. For example, red⁡((a⁢b)⁢(b⁢c))=a⁢b⁢c. With one bit per input variable, the resulting monomial’s mask is the bitwise OR of the two input masks.

Negation is the arithmetic operation 1−p. In a collected Boolean-valued polynomial, the constant coefficient toggles between 0 and 1 and the other coefficients change sign. The number of nonzero terms changes by one.

3. Work a network through the forward transformation

A full adder takes bits A and B and a carry-in C. Its sum bit D is 1 on odd parity. Its carry-out E is 1 when at least two inputs are 1.

D=A⊕B⊕C,E=(A∧B)∨(A∧C)∨(B∧C).

First translate A XOR B to t=a+b−2⁢a⁢b. Applying the XOR rule to t and c gives the sum polynomial d. Applying the AND and OR rules to the carry expression gives e.

d=t+c−2⁢t⁢c=a+b+c−2⁢a⁢b−2⁢a⁢c−2⁢b⁢c+4⁢a⁢b⁢c,e=a⁢b+a⁢c+b⁢c−2⁢a⁢b⁢c.

4. Recover the Boolean expression

The back-transformation removes one true input row at a time. Start with the reduced polynomial for the output of interest and keep the original input list throughout.

  1. Select a term. Among the nonzero terms, choose one with the fewest variables. Break ties in any order. Its coefficient will be +1.
  2. Read its row. Give each variable in the selected term value 1 and give every other input value 0. The constant term selects the all-zero row.
  3. Save a complete AND term. Use each input once, positively for a 1 and negated for a 0. For example, with inputs A, B, C, selecting a gives A∧¬B∧¬C. Its algebraic row polynomial is a⁢(1−b)⁢(1−c).
  4. Remove that row. If m is the row polynomial, replace p by red⁡(p⁢(1−m)). In Boolean terms, this is AND with the inverse of the complete term just saved.
  5. Repeat until the remainder is zero. OR the saved terms together. An empty list gives FALSE.

In symbols, vS is the row with ones at the indices in S. The complete row polynomial and the update are

mS⁡(x)=∏i∈Sxi∏j∈N∖S(1−xj),pnew=red⁡(p⁢(1−mS)).

For the full adder’s sum bit, start with p0=a+b+c−2⁢a⁢b−2⁢a⁢c−2⁢b⁢c+4⁢a⁢b⁢c. Choosing a first is one valid tie choice. In the first pass, the row polynomial expands to a−a⁢b−a⁢c+a⁢b⁢c.

The recovered expression is the OR of the four saved terms.

D=(A∧¬B∧¬C)∨(¬A∧B∧¬C)∨(¬A∧¬B∧C)∨(A∧B∧C).

Its four terms specify exactly the four rows with sum bit 1. This form is called canonical disjunctive normal form. It gives the full set of true assignments, which can also be expressed in a shorter form such as the original XOR network.

Use an output as a constraint

When the aim is to find inputs satisfying several conditions, build a signal that is true precisely when all the conditions hold. For a signal required to be 1, use its polynomial. For a signal required to be 0, use its complement. Multiply the conditions and reduce, then extract the true rows of the product.

For example, the full-adder condition D=1, E=0 has polynomial d⁢(1−e). Its true rows are 100, 010, and 001. A zero reduced polynomial means that no Boolean assignment satisfies the combined condition.

5. Why the back-transformation works

The proof of Roland Adorni’s back-transformation procedure was developed by ChatGPT 6.1 Sol High.

The guarantee. For any reduced polynomial that outputs 0 or 1 at every Boolean input, every minimum-degree choice has coefficient +1. The process extracts each true row once and terminates in exactly as many steps as there are true rows, at most 2n.

  1. The selected coefficient is the value of its row. At vS, a monomial xT survives exactly when T⊆S. For a selected support S, every proper subset has lower degree, so its coefficient is zero. Thus p⁡(vS)=∑T⊆ScT=cS. A nonzero coefficient equal to a Boolean output must be 1.
  2. The update changes one row. mS equals 1 at vS and 0 everywhere else. Multiplying by 1−mS clears the selected row and preserves all others. Reduction preserves those values, so the remainder is again Boolean-valued.
  3. All-zero outputs force a zero polynomial. If a nonzero reduced polynomial had all-zero outputs, evaluating it at the row for a minimum-degree term would produce its nonzero coefficient. That is a contradiction. The same argument applied to the difference of two reduced polynomials establishes uniqueness of their reduced representation.
  4. The saved rows give the original function. Each pass removes one true row. When all have been removed, the remainder is zero and the OR of the saved terms gives exactly the original true rows.

The proof applies to any finite Boolean input count and to each output of a combinational network. It relies on power reduction, collecting like terms, exact arithmetic, and the minimum-degree selection rule.

What the audit tried to break

For p=1−a−b+a⁢b, the term a⁢b has coefficient +1 but would incorrectly select 11. Minimum-degree selection gives the constant and correctly extracts 00. For p=a−a2, choosing a term before reducing would also fail. Reduction gives zero, matching every row.

The audit checked all 65,814 Boolean functions with zero through four inputs, including all 104,879 distinct legal transitions across every tied choice. It also checked the reasoning independently by expanding a polynomial as the sum of its true-row terms.

Subtract the extracted row directly

At the selected row, both p⁢mS and mS equal 1. At every other row both equal 0. By uniqueness, the reduced product equals the expanded row polynomial. Therefore

red⁡(p⁢(1−mS))=p−mS.

This avoids multiplying the entire remainder by the inverse. Expand the row polynomial and subtract it term by term. Its leading monomial is exactly the selected term with coefficient +1. All other monomials contain additional variables, so only higher-degree coefficients change. A scan in increasing degree can continue forward, provided it accounts for newly nonzero higher-degree terms.

6. Multiply without expanding every pair of terms

While reviewing Roland Adorni’s old notes, ChatGPT suggested using established transform algorithms to accelerate multiplication. The fast methods in this section and section 7 are proposed extensions, illustrated with pseudocode; Roland Adorni has not implemented them.

With k nonzero terms in one operand and l in the other, direct multiplication visits at most k⁢l term pairs. For each pair, multiply the coefficients and add the result to the coefficient indexed by the union of the variable sets. With dense operands on n inputs, this can take O⁡(4n) arithmetic operations.

The faster dense method changes the representation temporarily. The subset zeta transform maps the coefficient array c to the polynomial’s values at all Boolean input rows. The subset Möbius transform reverses that map. These are established algorithms proposed here for use with AlgebraicBoolean; see reference 1.

For an intuitive explanation of the complete multiplication method, start with reference 3. For a short academic treatment of the transforms and their fast computation, see reference 4, sections 2.1–2.3.

zS=p⁡(vS)=∑T⊆ScT,cS=∑T⊆S(−1)|S∖T|⁢zT.

Evaluating a product at a row gives the product of its evaluations there. Transform both operands, multiply corresponding entries, and apply the inverse transform to the product array. This computes the reduced product in the original encoding. Because multiplying monomial masks uses bitwise OR, this operation on coefficients is called OR convolution.

The following pseudocode uses an array indexed by bit mask. In each pass, bit has one bit set. In the inverse loop, subtraction undoes the additions of the forward loop.

subset_transform(array, number_of_variables, inverse):
    for i from 0 to number_of_variables - 1:
        bit = 1 << i
        for each mask with bit set:
            lower = mask XOR bit
            if inverse:
                array[mask] -= array[lower]
            else:
                array[mask] += array[lower]

multiply(left, right):
    transform both coefficient arrays forward
    multiply corresponding entries into an array
    transform that array with inverse = true
    return the resulting coefficients

Only variables occurring in either operand need array positions. With r such variables, compress their bit positions to a contiguous range before the transform and expand them back afterward. For positive r, the dense method uses O⁡(r⁢2r) arithmetic operations and O⁡(2r) array storage. Constant operands can be handled directly. These bounds count arithmetic operations, and their actual cost also depends on coefficient size.

For a sequence of gates, values can stay in the transformed representation. Each array then holds a truth table, and gates act row by row. Recover coefficients when a symbolic polynomial is needed. If the final result is already a truth table, its true rows can be read directly.

7. The signed representation

Encode FALSE as −1 and TRUE as +1. The original bit x and its signed counterpart s are related by

x=1+s2,s=2x−1.

Apply the change of encoding to the inputs and output. If p is the original polynomial and F the signed polynomial, the two directions are

F⁡(s)=2p⁡(1+s12,…,1+sn2)−1,p⁡(x)=1+F⁡(2x1−1,…,2xn−1)2.

Here s and x in function arguments denote the full input vectors. After substitution, reduce with the rules of the destination encoding. In the signed form, si2→1, so even powers reduce to 1 and odd powers reduce to the variable. In the original form, xi2→xi. Convert a signed result back to 0/1 before using the back-transformation above.

The signed encoding makes input polarity symmetric. Inverting one input substitutes its negative, which reverses signs of terms containing that input while preserving their supports. Complementing the output negates the whole polynomial.

For example, let s, t, u be the signed inputs for A, B, C. In the 0/1 encoding, the function true only at 111 is a⁢b⁢c, and the function true only at 000 is (1−a)⁢(1−b)⁢(1−c). The latter expands to eight terms. In signed form the two functions are

F111=−3+s+t+u+s⁢t+s⁢u+t⁢u+s⁢t⁢u4,F000=−3−s−t−u+s⁢t+s⁢u+t⁢u−s⁢t⁢u4.

Both signed polynomials have eight terms with equal coefficient magnitudes. Three-input parity shows the opposite tradeoff. The seven terms in the original full-adder sum collapse to D′=s⁢t⁢u in the signed encoding.

Fast multiplication in the signed encoding

Repeated signed variables cancel in pairs. For example, red⁡((s⁢t)⁢(t⁢u))=s⁢u. The resulting monomial contains the variables appearing in exactly one factor, so multiplication combines the masks by bitwise XOR. This is XOR convolution. The Fast Walsh–Hadamard Transform (FWHT) computes it by a sum-and-difference pass for each input bit. For a basic description of the transform and its fast algorithm, see the Wikipedia articles in reference 2.

hadamard_transform(array, number_of_variables):
    for i from 0 to number_of_variables - 1:
        bit = 1 << i
        for each mask with bit clear:
            other = mask OR bit
            low = array[mask]
            high = array[other]
            array[mask] = low + high
            array[other] = low - high

Write H for this unnormalized transform on arrays of length L=2r. Applying it twice multiplies the original array by L. For signed coefficient arrays c and d, the product coefficients are

H⁡(H⁡(c)⊙H⁡(d))L.

The symbol ⊙ means pointwise multiplication. A row bit of 1 in the transform’s output corresponds to a signed input of −1, since a monomial picks up a negative sign for each such bit it contains. This convention is the reverse of the original truth-row convention for each input bit.

As with the subset transforms, the dense method takes O⁡(r⁢2r) arithmetic operations and O⁡(2r) storage for positive r. A full dense transform visits the whole array regardless of how many coefficients are zero. In the straightforward loops above, each FWHT pair takes a sum and a difference, while each subset-transform pair takes a single addition or subtraction. Actual timings depend on the implementation and coefficient arithmetic.

Signed coefficients are exact fractions with powers of two in the denominator. With n inputs, a signed Boolean polynomial has coefficients that can be stored with common denominator 2n, because its coefficient array is the transform of the signed truth table divided by 2n. Exact fractions or scaled integers preserve cancellation. Rescaling the encoding to −½ and +½ is also possible, with square rule si2→14 in those coordinates. The −1/+1 choice gives the simpler mask rule.

8. Choose a multiplication method

A practical implementation can begin in the original 0/1 encoding and choose how to multiply each pair of polynomials. The term counts, active input count, and distribution of supports all affect the choice.

Three cases for the original encoding
CaseMethodWhat governs the cost
SparseStore only nonzero terms. Multiply the term pairs and collect by mask.Up to k⁢l pairs for term counts k and l.
IntermediateKeep sparse groups on some variables and transform the remaining variables within each group.The number of occupied groups and the size of each transformed array.
DenseApply the subset transforms over the union of the active variables.O⁡(r⁢2r) arithmetic operations for r active variables.

For the intermediate method, split the variables into two sets. Use monomial masks on the first set as group keys and treat the coefficients in each group as polynomials in the second set. Transform those inner polynomials. For each pair of occupied groups, multiply their inner arrays pointwise and add the result to the group whose key is the bitwise OR of the two keys. Apply the inverse transform to each resulting group. This follows by distributing the product across the groups. The choice of split and its performance still need benchmarking.

Switching between the original and signed encodings can be worthwhile when an expression becomes much sparser in the other form. A conversion can also expand the expression, as the single-row examples show. A result can stay in its chosen encoding until a later gate needs another representation. The relevant costs are multiplication, conversion, and how often later gates can reuse the converted form.

Dense transforms reduce the cost of multiplying expanded polynomials, while the largest arrays still grow exponentially with the number of active inputs. Benchmarking will determine when to switch among the methods on actual networks.

Earlier C# implementations

LinearBoolean3 implemented the original expanded 0/1 notation with integer coefficients and a variable mask per term. Its archived verification loop checked every three-input truth table. BLB extended the stored factors with negated literals and xA, the signed factor 2a−1. It used that representation in experiments with Golomb rulers, SHA-256 stages, and Keccak.

An earlier program, BLB, experimented with retaining negated literals inside terms. A term written A!B!C could stand for a⁢(1−b)⁢(1−c) without expanding it. This allowed direct rules such as red⁡(a⁢(1−a))=0 and could keep the written expression smaller. The expanded form used in the proof collects terms by their variable sets. Factored literal forms are a separate representation that can be explored alongside it.
